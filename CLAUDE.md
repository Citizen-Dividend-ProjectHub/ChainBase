# CLAUDE.md

Product/architecture context lives in `AI_README.md` — read that first for what ChainBase is, the locked architecture decisions, and current scope. This file covers the **frontend design system** ("Aurora"), so new UI work stays visually consistent instead of drifting back toward ad hoc styling.

## Design system rules

- **Never hardcode hex/rgba for brand colors.** Use the `--cb-*` CSS custom properties defined in `frontend/src/index.css` (`--cb-bg`, `--cb-text`, `--cb-muted`, `--cb-card`, `--cb-fill`, `--cb-border`, `--cb-border-strong`, `--cb-hero-grad`, `--cb-title-grad`, `--cb-blue`, `--cb-green`, `--cb-gold`, `--cb-red`, `--cb-primary-grad`, `--cb-conic`, `--cb-hairline`). The old token names (`--bg`, `--border`, `--text`, `--green`, etc.) still exist as aliases for backward compatibility — prefer the `--cb-*` names in new code.
- **Light/dark is automatic.** `:root` holds the dark values; `.cb-light` (toggled on `document.body` by `ThemeContext`, see `frontend/src/context/ThemeContext.jsx`) overrides them. Never branch styling logic on a JS theme check when a CSS variable will do — write the CSS once against the token and both themes fall out of it for free.
- **Reuse the shared shell**, don't rebuild it: `frontend/src/components/Sidebar.jsx` + `frontend/src/components/TopBar.jsx` (theme toggle, wallet pill, avatar) + the four `.glow-blob` divs rendered once in `App.jsx`'s `ProtectedLayout`. A new authenticated page is just a route rendered inside that shell — it doesn't add its own header/nav chrome.
- **Reuse the primitives**: `StatCard` (`hue` prop: `'blue' | 'green' | 'gold' | 'red'`, plus `label`/`value`/`sub`), `Badge` (status string → color, see the `MAP` in `Badge.jsx`), `Avatar` (conic-gradient ring + initials), and the shared CSS classes `.card`, `.card-table` (adds the 4-color gradient top hairline for table-containing cards), `.stats-grid`, `.btn`/`.btn-green`/`.btn-outline`, `.modal`, `.form-group`/`input`. Don't invent a one-off card/table/badge style inline.
- **Typography**: Plus Jakarta Sans for UI text (already the default `body` font), JetBrains Mono (`var(--font-mono)`) for anything numeric/technical — tx hashes, wallet addresses, countdowns. Hero numerics (balances, big stat values, page titles) are gradient-clipped text using `.cb-hero-grad` / `.cb-title-grad` or an inline `background-image` + `-webkit-background-clip:text` + `backgroundClip:'text'` + `color:'transparent'`, with `font-variant-numeric: tabular-nums` (`.tabular` class) on any numeric display.
- **Radii**: small UI (buttons/inputs/badges) use `var(--radius)` (12px); generic cards use `var(--radius-lg)` (20px); hero/table cards use `var(--radius-xl)` (24px). Don't pick arbitrary radius values.
- Mock/prototype data must be wired to real API calls before shipping — never leave sample data in a merged page. If a metric isn't backed by an existing endpoint, derive it from data the app already fetches (see `Dashboard.jsx`'s funding-pool runway calculation for the pattern) rather than adding a new backend endpoint just for a display convenience, unless the feature genuinely needs one.
